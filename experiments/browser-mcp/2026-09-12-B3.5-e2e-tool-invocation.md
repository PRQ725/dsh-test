## 1. 目标

验证 Agent 实际调用 Playwright MCP tool 后，能否走通：

```
DSH Agent
  → dsh-mcp-client
  → MCP
  → @playwright/mcp
  → Playwright
  → 本机 Chrome
  → 网页
```

即完成一次**最小化的真实浏览器操作**。

## 3. 执行与结果

### 3.1 前置盘点（turn 1）
- 确认 `evidence/config-dumps/browser-lab-composed-tree-AFTER-mcp.yml`（当时名为 `browser-lab-dump-AFTER-3.4.yml`）中 `mcp-playwright` entry 存在（grep 命中 4 处：L541-549）。

- 盘点 Chrome 进程与 MCP server 子进程（baseline：MCP server 无子进程）。

### 3.2 E2E 调用（turn 2）
请求（用户消息原文要点）：
> 1. 调用 `mcp__playwright__browser_navigate`，打开 `https://example.com`
> 2. 等待页面正常加载
> 3. 调用 `mcp__playwright__browser_snapshot`，获取当前页面的 accessibility snapshot

**实际 tool call #1** [FACT]
```json

```
**实际结果** [FACT]
```
### Ran Playwright code
await page.goto('https://example.com');
### Page
- Page URL: https://example.com/
- Page Title: Example Domain
### Snapshot

```

**实际 tool call #2** [FACT]
```json
{ "name": "mcp__playwright__browser_snapshot", "arguments": {} }
```
**实际结果** [FACT]
```yaml
### Page

- Page Title: Example Domain
### Snapshot

  - heading "Example Domain" [level=1] [ref=e3]

  - paragraph [ref=e5]:
    - link "Learn more" [ref=e6] [cursor=pointer]:

```

### 3.3 进程级旁证 [FACT]
- Chrome 由 `playwright-mcp --browser=chrome` 的进程谱系拉起：
  ```
  node.exe  "...\npm-cache\_npx\9833c18b2d85bc59\node_modules\.bin\..\@playwright\mcp\cli.js" --browser=chrome
  cmd.exe   cmd /d /s /c playwright-mcp --browser=chrome
  ```
- 观测到新增 Chrome renderer 子进程（`--type=renderer --extension-process ...`），parent 为既有 Chrome 主进程。
- `.playwright-mcp\` 目录**不在** workspace 下（`workspace .playwright-mcp exists: False`）；snapshot 文件写在 MCP server 进程的 cwd 相对路径下。
