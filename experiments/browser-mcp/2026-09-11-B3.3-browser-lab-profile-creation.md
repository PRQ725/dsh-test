## Command Executed

```powershell
dsh --profile browser-lab --from-default-profile web
```

实际展开为（本机 `dsh` 是 npm shim）：

```powershell
node "C:\Users\user02\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\lib\bin.js" `
     --profile browser-lab --from-default-profile web
```

### 命令的两阶段语义（源码确认，执行前已核对）

`apps/cli/lib/profile-boot-Dk-7KqJc.js`：

- **L207** `prepareProfile()` → `if (fromDefaultProfile !== void 0) initializeProfileFromDefault(...)`
- **L142–147** `initializeProfileFromDefault()` → `resolveProfileDir` + `PROFILE_TEMPLATES[fromDefaultProfile]` + `initProfile(...)`
- **L283** `composeProfile(...)` → **L311** `boot(...)`

即 **`--from-default-profile` 是"创建 + 立即 boot"的一体命令**，不是"只创建"。
创建发生在 boot **之前**，两者是串行的两个阶段。

### 执行结果：**创建成功，boot 阶段失败（端口冲突）**

```
Error: dsh: plugin tree failed to load: failed to apply loader entry include (cordis:include):
failed to apply loader entry webserver (@deepseek-ai/dsh-host-webserver):
listen EADDRINUSE: address already in use 127.0.0.1:3080
    at boot (…/dsh-app-boot/lib/index.js:1545)
    at async runProfile (…/dsh/lib/profile-boot-Dk-7KqJc.js:311)
    at async runCli (…/dsh/lib/bin.js:146)
```

**失败层级**：`webserver` 监听 3080 —— 被现有 GUI（PID 19696）占用。
**与 Profile 创建无关**：`initProfile` 在 boot 之前已完成，Profile 文件已落盘。
**失败现场已保留**：`browser-lab-create.log`。

> **注**：我的输出捕获管道把退出码报成了 `exit=0`，这是管道行为导致的**不可靠读数**；
> 真实结果是 boot 抛出了 `EADDRINUSE` 并以错误终止。以堆栈为准，不以该退出码为准。

## INFERENCE

1. **`--from-default-profile web` 做的只是"复制模板 + 初始化骨架"，不做依赖安装、不继承任何运行时状态。**
   证据：bundles 列表照抄；`dependencies` 仍为空；两个 patch/根文件是空模板；合成树与 web 完全相同。
   它**没有**从 web 复制 `node_modules` 内容，也**没有**复制 `.dsh-module-fallback` 的实际内容。

2. **创建与 boot 是可分离的两个阶段。** 因为创建先于 boot 完成，端口冲突只影响 boot。
   因此**用同一个端口参数重新 boot 即可**验证运行时，无需重新创建 Profile
   （即不需要再跑一次 `--from-default-profile`）。

3. **端口冲突是环境性的，不是 Profile 缺陷。** `browser-lab` 从 web 模板继承了 web app 的默认端口 3080，
   而 3080 被 GUI 占用 —— 这是**必然**结果，与 Profile 内容无关。

4. **`node_modules` 为空是正常的，不是创建失败。** 因为 `dependencies` 为空，
   没有东西需要链接/安装；运行时解析依赖走 `profiles/node_modules` 的启动器级回退目录。
   `.dsh-module-fallback` 的存在说明 `initProfile` 会预置该目录骨架。

5. **隔离性是结构性的，不是约定性的。** 两个 Profile 各有独立目录与独立合成；
   home patch 不存在，因此不存在跨 Profile 的配置注入路径。
   本次也**实证**了创建 `browser-lab` 不会触碰 `web`。

6. **dump-config 对 custom Profile 有效且可信**（exit=0、与 web 逐字节一致），
   说明这套只读校验方法可以复用于后续阶段（例如加入 MCP 条目后再次对比）。
